# Research

Answer the decision behind the question, not every adjacent question the search
surface reveals.

## Establish the claim

State the question, the decision it informs, and what would count as enough
evidence. Check repository code and documentation first when the claim concerns
the current project. Separate facts, inferences, and preferences.

## Gather evidence

Prefer sources in this order:

1. Primary evidence: official documentation, specifications, source code,
   release notes, datasets, filings, or research papers.
2. Independent high-quality analysis when interpretation or comparison matters.
3. Community reports only for lived experience that primary sources cannot
   provide.

Verify unstable facts at the time of the request. Search for disconfirming
evidence, not only support for the leading answer. For consequential claims,
use more than one independent source when available. Do not disguise a search
snippet, generated summary, or uncited assertion as evidence.

Delegate independent lines of inquiry when they can run in parallel, but verify
their important claims against the sources before reporting them.

## Synthesize

Lead with the conclusion and its practical consequence. Include:

- evidence for the claims that drive the conclusion, cited at the point of use;
- meaningful disagreement, limitations, or uncertainty;
- the strongest rejected alternative and why it lost;
- the next action when the research was meant to unblock work.

Link directly to sources. Quote only when exact wording matters; otherwise
paraphrase. Return the result in the conversation by default. Create a durable
research artifact only when the user asks for one or a downstream workflow
requires a stable input, and then use the repository's existing location.
